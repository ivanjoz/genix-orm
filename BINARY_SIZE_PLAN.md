# genix-orm Binary Size — Analysis & Refactor Plan

Status: **Phases 0–3 DONE** (Phase 2 partially — see §6.2). Production binary
**54,263,970 → 49,152,160 (−5,111,810, −9.42%)**, genix-orm attributed
**20,466,224 → 15,717,298 (−4,748,926)**, its share of the binary 37.1% → 34.7%.
Phases 4–5 not started. **Live-run verification still owed** on the Phase 1 recalc pair (§6.1).
Actual results in §6.1; §6.2 records why the Phase 2 and 3 estimates were wrong.

Goal: cut genix-orm's contribution to the backend binary roughly in half — an estimated
**8–10 MB off a 54 MB Lambda** — without changing the public query API and without touching any
per-row hot path.

The whole problem is one thing: **Go stencils a separate machine-code copy of every generic
function for every concrete type it is instantiated with**, and the bodies of those functions
do not actually use the type parameters. They already work through `reflect`, `unsafe.Pointer`
and the `IColInfo`/`Coln` interfaces. The type parameters are plumbing at the signature, and we
pay for 54 tables' worth of duplicate copies of code that is byte-for-byte identical in intent.

## 1. Measured baseline

Build used everywhere in this document — the real production target from `backend/deploy.sh`:

## 2. Diagnosis (measured)

### 2.1 The duplication ratio

**19,225 compiled functions from 19,234 lines of source.** That one-to-one ratio is the finding.

| Category | Functions | Bytes |
| --- | --- | --- |
| Plain non-generic code | 640 | 538,128 |
| Singleton instantiations | 4,497 | 2,889,464 |
| **Duplicated instantiations of 427 distinct source functions** | **14,728** | **16,719,837 (85%)** |

427 source functions become 14,728 compiled copies — **34× average duplication**.

Function *names alone* cost **2,931,345 bytes** in pclntab, because every instantiation carries a
name like
`scylla.ScyllaController[app/webpage/types.EcommercePageContent,app/webpage/types.EcommercePageContentTable].RecalcVirtualColumns`.

### 2.2 Full stenciling, not shape sharing — and `T` is the multiplier

Go is emitting one copy per **concrete type pair**, not per gcshape. `Col.Between` exists **258
times**, with type arguments recorded as concrete types (`app/accounting/types.AssetTable,int16`),
one per (table, column-type) combination. `Col[AssetTable,int16]` and `Col[ProductTable,int16]`
are separate machine code.

This means the cost **scales with table count**: roughly **130 KB of binary per table**. At 54
tables today that is the 20.5 MB; at 100 tables it would be another ~6 MB.

### 2.4 The bodies do not use the type parameters

This is what makes the fix free. Read from the current source:

- **`makeTable[T]`** (`scylla/reflect.go:213`) — calls `(*structType).GetSchema()`, then
  `reflect.ValueOf(structType).Elem()`, then works entirely through `reflect` and the `Coln`
  interface. `T` appears twice, both on the first two lines. Runs **once per table at init**.
- **`resolveUpdateColumnsForWrite[T,E]`** (`scylla/insert-update.go:1140`) — the first two lines
  derive the table (`db.InitStructTable[E,T](new(E))` → `getOrCompileScyllaTable`); the remaining
  ~190 lines operate on a concrete `ScyllaTable` and `[]IColInfo`. The `records *[]T` parameter is
  touched in exactly one block, via `xunsafe.AsPointer(&(*records)[i])` handed to
  `column.GetRawValue(ptr)` — **already `unsafe.Pointer`**. `T` supplies nothing but the slice
  element stride.
- **`Col[T,E].DecimalSize` / `Int32` / `IsWeek` / `CompositeBucketing` / `Autoincrement`**
  (`db/column.go`) — bodies touch only `q.info`, a plain `ColumnInfo`. Neither `T` nor `E` appears
  in the body. Schema-declaration time only.
- **Predicates** `Equals` / `GreaterThan` / `LessThan` — one-liners that immediately box with
  `any(v)` and delegate to `addStatement`.

## 3. The pattern: thin generic façade over one non-generic core

Keep the generic signature so call sites stay type-safe and unchanged. Make the body a shim that
type-erases and calls a single shared implementation. Go still stencils the shim per instantiation,
but at a few dozen bytes instead of ~1,000.

```go
// TODAY — the append logic is copied in full for each of 258 (T,E) pairs
func (e *Col[T, E]) addStatement(operator string, value any) *T {
	e.tableInfo.Statements = append(e.tableInfo.Statements,
		ColumnStatement{Col: e.info.Name, Operator: operator, Value: value})
	return e.schemaStruct
}

// AFTER — logic exists once; the generic part shrinks to a shim
func (c *colCore) addStatement(operator string, value any) {   // non-generic: ONE copy
	c.tableInfo.Statements = append(c.tableInfo.Statements,
		ColumnStatement{Col: c.info.Name, Operator: operator, Value: value})
}

func (e *Col[T, E]) GreaterThan(v E) *T {   // still stencilled ×258, but tiny
	e.core.addStatement(">", v)
	return e.schemaStruct
}
```

`GreaterThan(v E) *T` keeps its exact signature. All 480 predicate call sites in the backend
compile unchanged, with identical type safety.

For package-level functions the equivalent move is to pass the already-erased values the body
actually uses — `ScyllaTable`, `[]IColInfo`, a record count and an accessor — instead of `[T,E]`.

**Why this does not cost performance:**

- The `any(v)` boxing already happens today; no new allocations are introduced.
- `ScyllaTable` is already passed and copied by value throughout the write path.
- Less code means better instruction-cache behaviour.
- The one real cost is an indirect call where there was a direct one. Every function in scope is
  called at **init, deploy, or per-batch** granularity — never per row.

## 4. Measured proof point

`resolveUpdateColumnsForWrite` was converted as a throwaway experiment: signature changed from
`[T,E](records *[]T, …)` to `(scyllaTable ScyllaTable, recordCount int, recordPointerAt func(int) unsafe.Pointer, …)`,
with the two call sites passing a closure. ~20 lines changed.

| | Before | After | Delta |
| --- | --- | --- | --- |
| Production binary (`-s -w`, arm64) | 54,263,970 | 53,739,682 | **−524,288 (−0.97%)** |
| genix-orm attributed | 20,466,224 | 19,889,342 | −576,882 |

`go build ./...` passed. **The experiment was reverted**; `scylla/insert-update.go` is
byte-identical to its pre-experiment state.

Predicted from the §2.3 tally: 628,596. Measured: 576,882. The estimation model is accurate to
within ~8%, which is what the per-phase estimates in §6 are built on.

## 5. Explicitly out of scope

### 5.1 Changing `Col[T,E]` to `Col[E]` — rejected

`db.Query(&orders)` returns `*E`, the **schema struct** (`*SaleOrderTable`), whose fields *are*
the columns. Every predicate returns that same struct, and that is the entire chaining mechanism:

```go
query.ClientID.Equals(clientID).DetailProductsIDs.Contains(productID)
```

`.Equals(clientID)` hands back `*SaleOrderTable` so that `.DetailProductsIDs` — a struct field — is
reachable. A non-generic query handle cannot have per-table fields, so the API would become
`db.Query(&orders).Where(t.CompanyID).Equals(cid)`, rewriting **480 predicate call sites across
119 files**.

Estimated additional saving over the §3 shim approach: **~1.4 MB**. Not worth a repo-wide query
rewrite. The shim recovers most of `db/column.go` with zero API change.

### 5.2 Per-row hot paths — do not touch

Anything called inside the row encode/decode loop stays exactly as it is. That is where
devirtualization and direct calls actually matter, and it is not where the bytes are.

### 5.3 Go 1.27 generic methods — measured, does not help

Generic methods are a namespacing feature. Stencil count is driven by the number of distinct type
arguments at instantiation sites; moving a type parameter from a package-level function onto a
method changes where the declaration may be written, not how many copies are emitted.

Confirmed empirically — rebuilding with Go 1.27.0 and **no source changes**:

| | Go 1.26.2 | Go 1.27.0 | Delta |
| --- | --- | --- | --- |
| Production binary | 54,263,970 | 53,477,536 | **−786,434 (−1.45%)** |
| genix-orm attributed | 20,466,224 | 19,812,682 | −653,542 |
| **genix-orm compiled functions** | **19,225** | **19,212** | **−13** |

Only 13 functions merged. The saving is general codegen improvement, already net of the +60 KB the
new size-specialized malloc adds. **Go 1.27 does not reduce stenciling at all.** The upgrade is
worth taking (§6, Phase 0) but it is orthogonal to this refactor.

Also note: moving `T` off `Col` and onto its methods is not expressible anyway — `T` appears only
in *return* position, where Go cannot infer it, and `schemaStruct *T` is a struct field, which
cannot reference a method's type parameter.

### 6.2 Why the Phase 2 and 3 estimates were wrong

Two things the §2.3 byte tallies could not see.

**Phase 2 — not every type parameter is plumbing.** Only two of the five targets were convertible.
`resolveUpdateColumnsForWrite` and `executeViewTableSyncChunk` use their records purely as an
`unsafe.Pointer` source, so `(recordCount, recordPointerAt func(int) unsafe.Pointer)` replaces them
exactly. The other three do not:

- `Merge` builds `[]T` insert and update slices and takes `func(prev, current *T) bool` callbacks.
- `executeInsertUpdateBatch` concatenates `[]T` and threads it through generic helpers
  (`runSelfParseIfDefined`, `fetchManagedCounterValues`).
- `execIndexGroupQuery` constructs the caller's `RecordGroup[E]` result containers.

In all three the type parameter is load-bearing: they *produce* typed values rather than reading
through them. Converting them would mean reflection-built slices on the insert path — the hottest
write path in the ORM — for ~983 KB. **Not done, and not recommended.**

**Phase 3 — the cost is metadata and inlining, not body size.** The façade alone bought
**65 KB of an estimated 2.5 MB**. Measured cause, in `db/column.go` after the change:

| | Bytes |
| --- | --- |
| code | 1,836,768 |
| pclntab | 2,410,098 |
| …of which function *names* | 646,326 |

**pclntab exceeds the code.** Each of ~6,000 instantiations carries a fixed metadata floor —
name, pcsp, pcln, pcdata tables — that shrinking its body cannot touch. Worse, `go build -gcflags=-m`
showed every `colCore` core was being inlined straight back into each instantiation, so the shared
body was not actually shared. Marking the statement builders `//go:noinline` recovered 590 KB, and
collapsing `GetInfo`/`GetInfoPointer` to take a type *name* instead of the type parameter added 131 KB.

The remaining ~4 MB in `db/column.go` is structural: ~6,000 distinct functions each paying the
metadata floor. **The only lever that touches it is reducing the instantiation count**, which means
the `Col[T,E]` → `Col[E]` change rejected in §5.1. That rejection still stands — but its price is
now known to be higher than the 1.4 MB estimated there, since the estimate assumed the shim
approach would recover more than it did.

**Lesson for Phases 4–5:** estimate from instantiation *count*, not summed bytes. A target is worth
converting only when its type parameter is a pure pointer/reflection source *and* its body is large
enough that per-function metadata is not the dominant cost.

**Verification owed.** `RecalcVirtualColumns` and `RecalcGroupIndexHashes` have **no test
coverage** — they are reachable only through the `fn-recalc` exec handler — and P1c changed how
their per-row record is allocated (`*new(T)` → `reflect.New(recordType).Elem()`, pointer taken with
`Addr().UnsafePointer()` instead of `xunsafe.AsPointer`). Field offsets are identical and the whole
body already addressed the record through `IColInfo.SetValue`/`GetStatementValue`, so this is
mechanically equivalent — but it writes recalculated virtual columns back to the database and
**must be exercised against a live table before it ships**.

### Phase 0 — Go 1.27

Bump `toolchain` in `backend/go.mod` and the three ORM `go.mod` files. Note the runtime
traceback-labels change is gated on the `go` directive, not the toolchain, so leaving `go 1.26` in
place avoids that behaviour change. `golang.org/dl/go1.27` is not published yet, but Go's own
`toolchain` directive auto-downloads 1.27.0 on first build, so no system install is needed.

**Side finding, unrelated to this plan:** `cd scripts && go run . check_tables` was failing with
`internal error: package "runtime" without types was imported from "app/libs/servermetrics"`. This
is `golang.org/x/tools` v0.41.0 being too old for the installed toolchain — it reproduces with
`toolchain go1.26.0`, so Phase 0 did not cause it. Fixed by `go get golang.org/x/tools@latest`
(v0.41.0 → v0.49.0) in `scripts/go.mod`; `check_tables` now passes, reporting 53 table struct pairs.

### Phase 1 — init and deploy time (zero hot path)

- `makeTable` (`scylla/reflect.go`) — 853 KB ×54. Pure reflection already; takes
  `(schema TableSchema, structRefValue reflect.Value)`. Its only caller is
  `getOrCompileScyllaTable`, inside a `sync.Once` — so it provably runs at most once per table
  type, for the life of the process. `getOrCompileScyllaTable[T]` itself uses `T` only for
  `reflect.TypeOf`, so it de-genericizes in the same change.
- `scylla/deploy.go` `ScyllaController` maintenance methods ×106 — `RecalcVirtualColumns` 609 KB,
  `RecalcGroupIndexHashes` 384 KB, `DeleteViewsAndIndexes` 358 KB, `ResetCounter` 312 KB. These are
  admin and deploy paths, not request paths.

### Phase 2 — write path, per batch not per row

- `resolveUpdateColumnsForWrite` — 629 KB. **Already prototyped and measured at 577 KB (§4).**
- `executeInsertUpdateBatch` — 554 KB.
- `executeViewTableSyncChunk` — 404 KB.
- `execIndexGroupQuery` — 218 KB.
- `Merge` — 211 KB.

The record-accessor closure (`func(int) unsafe.Pointer`) allocates once per call, not per row.
Confirm with a benchmark before and after on the insert path.

### Phase 3 — `db/column.go`

Introduce a non-generic `colCore` holding `info ColumnInfo` and `tableInfo *TableInfo`; embed it in
`Col[T,E]` and `ColSlice[T,E]`. Move every body that does not mention `T` or `E` onto `colCore`.
Generic methods survive as shims returning `*T`. Covers `SetSchemaStruct` (591 copies),
`GetInfoPointer` (333), `Autoincrement` (314), `DecimalSize`, `Between`, `In`, `Contains`,
`GreaterThan`, `GreaterEqual` and the rest of the modifier set.

**No public API change. No call site changes.**

### Phase 4 — the remaining generic surface

`db/tablestruct.go` (1.94 MB / 2,489 funcs), `scylla/executor.go`, `scylla/controller_generic.go`.
Higher risk because `TableStruct[D,T,E]` is embedded in every table schema struct and is closer to
the read path. Re-measure and reassess after Phase 3 — this phase may not be worth it.

### Phase 5 — knock-on

`<autogenerated>` compiler thunks (2.47 MB / 3,915 funcs) shrink automatically as the generic
surface shrinks. No work item; measure at the end.

## 7. Verification

genix-orm is **three separate Go modules** — `genix-orm` (scylla), `genix-orm/db` and
`genix-orm/dynamo`, each with its own `go.mod`. `go test ./...` at the ORM root only covers
`scylla` and `scylla/text_search`. All three must be checked.

Baseline, all green as of writing:

```sh
cd backend/genix-orm         && go build ./... && go test -count=1 ./...   # scylla 3.5s ok
cd backend/genix-orm/db      && go build ./... && go test -count=1 ./...   # ok
cd backend/genix-orm/dynamo  && go build ./... && go test -count=1 ./...   # ok
cd backend                   && go build ./... && go vet ./...
cd scripts                   && go run . check_tables
```

Per phase, additionally record the size delta:

```sh
cd backend && GOOS=linux GOARCH=arm64 CGO_ENABLED=0 go build -ldflags '-s -w' -o /tmp/main . && stat -c%s /tmp/main
```

Full attribution when a number looks wrong:

```sh
cd backend && GOOS=linux GOARCH=arm64 CGO_ENABLED=0 go build -o /tmp/main.sym . \
  && gsa --format html --output /tmp/size.html /tmp/main.sym
```

The ORM test suite is thin (23 test files across three modules) and there is no integration test
that exercises a real insert against Scylla in CI. Phases 2 and 4 touch the write path, so those
need manual verification against a live database before merging — the `database-records` skill
covers reading and writing real records.

## 8. Risks

1. **Thin test coverage on the write path.** The biggest risk in the plan. Phase 2 changes how
   records reach `GetRawValue`; a stride or offset mistake would produce silently wrong index
   validation rather than a crash. Mitigate by verifying against real records, not just unit tests.
2. ~~**`getOrCompileScyllaTable` must be idempotent and cached** for `ScyllaTable` to be safely
   hoisted to the caller.~~ **Resolved.** `scylla/table_cache.go:18` memoizes on
   `PkgPath + "." + Name` through a `sync.Map` plus a per-entry `sync.Once`. Hoisting the call to
   the caller is safe and free.
3. **Closure allocation.** Passing `func(int) unsafe.Pointer` allocates if it captures. Once per
   batch is fine; verify it does not land in a per-row loop.
4. **`genix-orm` is a separate repo.** Every phase must be committed *and pushed inside the
   submodule* — a root-level commit does not publish it.
5. **Estimates are extrapolations.** Only Phase 0 and part of Phase 2 are measured. If Phase 1
   lands materially under its ~2.2 MB estimate, re-derive the rest before committing to Phase 4.

## 9. Open questions

1. **Ship Phase 0 separately?** It is a one-line toolchain bump worth a measured 786 KB and has
   nothing to do with the rest. Recommend yes, as its own commit.
2. **Is Phase 4 wanted at all?** ~1.5 MB for the riskiest work in the plan, on code closest to the
   read path. Recommend deciding after Phase 3's measurement, not now.
3. **Does `dynamo/` matter?** It contributes nothing to the backend binary (not imported) but
   carries the same `Repo[T,E]` / `Col[T,E]` pattern. Left alone unless you want the consistency.
